## xlsx export format (SIT workbook)

`suite compile` and `export` write into `build/inventory/<kind>/` (kind =
suite yaml's `kind`, or `sit` for `export`): a timestamped
`<name>_<YYYYMMDD-HHMMSS>.xlsx` + `.md` pair plus a stable `<name>-latest.xlsx`
+ `-latest.md` copy (overwritten each run — this is what scripts/smoke/COM
snippets read); each workbook also has a `.json` sidecar (see below), in the 5-sheet format below - layout reference committed at
`tools/reference-format-sit.xlsx` (the reference SIT workbook layout, a
synthetic example generated by `tools/make_reference_workbooks.py`);
header-block values (project code/name, system, roles row) come from
`config.yaml → export:`.

- `A - Table of Contents` — project header, revision history, tab list
- `B - Proj Doc References` - CONCATENATE formulas off sheet A + adopted PRD: one `PRD` row per PRD the selected test cases draw on (title and adopted version); a single row naming the project when they draw on none
- `C-TC-<n> (<run name>)` - one per RUN (`run` on the SIT spec entry; one
  complete flow with one data profile; tc-style R6), numbered 1, 2, ... in the
  order the runs first appear and cut to Excel's 31-character limit
  (`run_sheet_name`), e.g. `C-TC-1 (Main flow)`, `C-TC-5 (Standalone checks)`.
  Test cases with no `run` (UAT, older content) keep one sheet per module,
  `C-TC-<sec> (<module>)` (§sec parsed from the module description). Two
  sheets that would share a name refuse the export. Columns A-N:
  ID / Scenario / Test Steps / Field / Values / Expected Results / AI
  Confidence / Remarks (F, G - tc-style R7: overall level, then one
  `Column: Level - remark` line per reviewed column), then a blank green
  execution grid (H-N: Actual Results … Remarks) for testers. Each sheet has
  its own blue header row and its own `<Pre-condition>` block (the lines shared
  by every TC on THAT sheet). A light-blue `Section:` row separates each flow
  section inside the sheet (there are no `Run:` rows: the sheet is the run).
  The chain line (`Continue from TC-...` / `Start of run:`, tc-style R6) is
  never lifted into the shared block; it leads each test case's Test Steps
  cell, so a sheet of all-start cases repeats `Start of run:` in every cell.
  Row order inside a sheet: module + PRD §s + sub-US ids; story/flow group
  rows; `Section:` rows; test cases. Per-TC precondition extras append to
  Field / Values as bare unlabeled lines (tc-style R5 - no `Pre-condition:`
  label). **Field / Values leads
  with the TC's concrete inputs** (`Field = value` lines from the TC's
  `# Test Data` section — tc-style contract, `.claude/skills/tc-style/`).
  Scenario = `Scenario/Given/When/Then` parsed from the covered
  AC's text (falls back to the TC objective), labels bold. Expected Results
  ends with the lettered element-verification block (a. b. c. …) for that
  AC's mapped components — see Gotchas. **Cell text is style-normalized on
  export** (`wiki_suite.py::_richify`): `**...**` markers become real bold
  runs; em/en dashes become hyphens (also applied to sheet names and group
  rows built from concept titles). IDs render as `TC-<wiki-id>` —
  the `Total TC =` COUNTIF and Test Statistics VLOOKUPs key off that prefix;
  wiki ids themselves are unchanged (no migrate-ids needed).
- `Test Statistics` — OVERALL block + one COUNTIF/VLOOKUP dashboard block per
  run sheet (titled with the run name; a runless set keeps one block per
  story/flow), status pulled from that C-TC sheet's column I
- `Change Log` - header row. `export` fills it: the draft says no changes
  yet, the final lists what the grade round changed (`eval_rubric --diff`).
  A suite compile leaves it header-only, for testers

### Sidecar and the app's Workbook view

Every compile also writes a sidecar beside the workbook, same name with a
`.json` suffix, timestamped plus a `-latest.json` copy
(`wiki_suite.py::write_sidecar`, called by `compile_suite` and `cmd_export`):

```json
{ "compiled_at": "<ISO time>", "wiki_commit": "<git HEAD>",
  "source": {"type": "suite", "name": "<suite>"},
  "tcs_order": "sheet",
  "tcs": {"testcases/sit/<module>/<id>": "sha256:<manifest tc_hash>"} }
```

For `export` the source is `{"type": "export", "name": "<name>", "story": "<STORY>"}`
(a flow export has `"flow": "<stem>"` in place of the story; a draft export has
`"name": "<name>-draft", "draft": true` and neither).
`tcs` lists exactly the test cases drawn in the workbook, in sheet and row order
(the same sheet plan the renderer draws, returned by `render_xlsx`);
`tcs_order: "sheet"` records that promise.

The operator app reads the `.xlsx` itself (`tools/app/workbook_model.py`,
`GET /api/workbook/<kind>/<file>`) and draws it at `#/workbook/<kind>/<file>`:
sheet tabs, a version picker with Download, a stale banner with Recompile (a
suite source, or an export that recorded a story, which runs the gated final
export; otherwise, a draft included, Download only), and
a review panel opened by clicking a test case row (Enter or Space too), whose
**Open in workbook** link (from the Test Cases grid) is inert when the test case
is in no workbook. Three
things in this file's format are load-bearing for that view, so keep them in
step when changing the renderer:

- **Formulas.** A workbook never opened in Excel has no cached values, so the
  read model evaluates what the renderer emits: `CONCATENATE`, `COUNTIF`,
  `COUNTA`, `VLOOKUP(..., FALSE)`, `IFERROR`, cell and `'Sheet'!$C$3`
  references, `+ - * /`. A new function in `render_xlsx` shows in the app as
  muted formula text ("calculated in Excel") until
  `workbook_model.py::_FUNCS` learns it.
- **Test case rows.** A row is a test case when column A of a `C-TC` sheet,
  below the header row, holds `TC-<id>` (or `BR-<id>`). The row is mapped to
  its ref through the sidecar, because a SIT id and a `UAT-` id display the
  same `TC-<id>`. With no sidecar the app falls back to the wiki's test cases
  of that kind and links only rows whose displayed id is unique; nothing is
  marked changed without a sidecar. A shared id is linked only when the sidecar has
  `tcs_order: "sheet"` and the counts match (a workbook compiled before that
  field leaves such rows unlinked until recompiled); a unique id always links.
- **Freshness.** A row is "changed" when the test case's sealed hash in
  `manifest.json` differs from the sidecar's, or the test case is now stale,
  retired or gone. A workbook with no sidecar, or one that is not what
  `write_sidecar` writes (missing or wrongly typed fields), shows
  `freshness unknown — recompile to track changes`; recompile it once to start
  tracking. Press Recompile if the banner offers it (it does when the source is
  known: with no sidecar the app infers it from the file name, a name matching
  `suites/<name>.yaml` is a suite and `<STORY>-sit`, `-uat` or `-osat` with an
  existing `stories/<STORY>.md` is an export). Otherwise rerun
  `py tools/wiki.py suite compile <name>` or
  `py tools/wiki.py export --story <id> --name <name>`. A `kind` outside
  `sit`, `uat`, `osat`, `mixed` is not found (HTTP 404), an
  unreadable workbook is HTTP 422 naming the file (not its directory), and the
  listing skips unreadable files and Excel `~$` lock files.

Verify formulas after touching the renderer (`tools/wiki_suite.py::render_xlsx`)
— recalc in real Excel via COM and scan for `#`-errors (verified working):

```powershell
$xl = New-Object -ComObject Excel.Application; $xl.Visible = $false
$wb = $xl.Workbooks.Open("C:\path\to\tc-copilot\build\inventory\sit\sit-all-latest.xlsx")
$xl.CalculateFullRebuild()
foreach ($ws in $wb.Worksheets) { $err = 0
  foreach ($c in $ws.UsedRange.Cells) { if ($c.Text -like "#*") { $err++ } }
  Write-Output ($ws.Name + ": errors=" + $err) }
$wb.Close($false); $xl.Quit()
```

Human-gated lifecycle & change commands (`retire`, `void-ac`, `unretire`,
`release`, `revert`, `approve-cr`, `reject-cr`) are documented in the
`tc-lifecycle` and `tc-change-report` skills.

Every mutating command auto-commits as `tc-agent <tc-agent@internal>`; append
`--no-commit` to batch several steps into one commit.

View the dashboard headlessly (verified end-to-end this session):

```powershell
py tools/wiki.py dashboard --no-commit
& "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe" --headless=new `
  --disable-gpu --window-size=1200,2600 `
  --screenshot="C:\path\to\tc-copilot\build\status\dashboard.png" `
  "file:///C:/path/to/tc-copilot/build/status/dashboard.html"
Start-Sleep -Seconds 5
Test-Path C:\path\to\tc-copilot\build\status\dashboard.png
```

The URL must be forward-slash `file:///C:/...` — a POSIX-style `file:///c/...`
path renders nothing (confirmed: 0 files written, only a harmless
`fallback_task_provider` stderr line). The process **detaches and returns
before the PNG is finished** — `$LASTEXITCODE` comes back empty/unreliable
even on success, so don't gate on it; wait a few seconds and check the file
exists instead. Write into `build/status/` (a dir you own) — writing to a
*pre-existing* file in `$env:TEMP` (e.g. one created by `New-TemporaryFile`)
silently produces a 0-byte file with no error text; a fresh path in
`build/status/` is the known-good target.
