## xlsx export format (SIT workbook)

`suite compile` and `export` write into `build/inventory/<kind>/` (kind =
suite yaml's `kind`, or `sit` for `export`): a timestamped
`<name>_<YYYYMMDD-HHMMSS>.xlsx` + `.md` pair plus a stable `<name>-latest.xlsx`
+ `-latest.md` copy (overwritten each run — this is what scripts/smoke/COM
snippets read), in the 5-sheet format below — layout reference committed at
`tools/reference-format-sit.xlsx` (the reference SIT workbook layout, a
synthetic example generated by `tools/make_reference_workbooks.py`);
header-block values (project code/name, system, roles row) come from
`config.yaml → export:`.

- `A - Table of Contents` — project header, revision history, tab list
- `B - Proj Doc References` — CONCATENATE formulas off sheet A + adopted PRD
- `C-TC-<sec> (<module>)` — one per module (§sec parsed from the module
  description; name abbreviated to Excel's 31-char limit). Columns A–L:
  ID / Scenario / Test Steps / Field / Values / Expected Results, then a blank
  green execution grid (Actual Results … Remarks) for testers. Section row =
  module + PRD §s + sub-US ids; story/flow group rows; preconditions shared by
  every TC lift into the blue `<Pre-condition>` block, per-TC extras append to
  Field / Values as bare unlabeled lines (tc-style R5 - no `Pre-condition:`
  label). **Field / Values leads
  with the TC's concrete inputs** (`Field = value` lines from the TC's
  `# Test Data` section — tc-style contract, `.claude/skills/tc-style/`).
  Scenario = `Scenario/Given/When/Then` parsed from the covered
  AC's text (falls back to the TC objective), labels bold. Expected Results
  ends with the lettered element-verification block (a. b. c. …) for that
  AC's mapped components — see Gotchas. **Cell text is style-normalized on
  export** (`wiki_suite.py::_richify`): `**...**` markers become real bold
  runs; em/en dashes become hyphens (also applied to sheet names and group
  rows built from concept titles). IDs render as `TC-<wiki-id>` —
  the `Total TC =` COUNTIF and Test Statistics VLOOKUPs key off that prefix;
  wiki ids themselves are unchanged (no migrate-ids needed).
- `Test Statistics` — OVERALL block + one COUNTIF/VLOOKUP dashboard block per
  story/flow, status pulled from the C-TC sheet's column G
- `Change Log` — header-only, filled by testers

Verify formulas after touching the renderer (`tools/wiki_suite.py::render_xlsx`)
— recalc in real Excel via COM and scan for `#`-errors (verified working):

```powershell
$xl = New-Object -ComObject Excel.Application; $xl.Visible = $false
$wb = $xl.Workbooks.Open("C:\path\to\tc-copilot\build\inventory\sit\sit-all-latest.xlsx")
$xl.CalculateFullRebuild()
foreach ($ws in $wb.Worksheets) { $err = 0
  foreach ($c in $ws.UsedRange.Cells) { if ($c.Text -like "#*") { $err++ } }
  Write-Output ($ws.Name + ": errors=" + $err) }
$wb.Close($false); $xl.Quit()
```

Human-gated lifecycle & change commands (`retire`, `void-ac`, `unretire`,
`release`, `revert`, `approve-cr`, `reject-cr`) are documented in the
`tc-lifecycle` and `tc-change-report` skills.

Every mutating command auto-commits as `tc-agent <tc-agent@internal>`; append
`--no-commit` to batch several steps into one commit.

```powershell
py tools/wiki.py dashboard --no-commit
& "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe" --headless=new `
  --disable-gpu --window-size=1200,2600 `
  --screenshot="C:\path\to\tc-copilot\build\status\dashboard.png" `
  "file:///C:/path/to/tc-copilot/build/status/dashboard.html"
Start-Sleep -Seconds 5
Test-Path C:\path\to\tc-copilot\build\status\dashboard.png
```

The URL must be forward-slash `file:///C:/...` — a POSIX-style `file:///c/...`
path renders nothing (confirmed: 0 files written, only a harmless
`fallback_task_provider` stderr line). The process **detaches and returns
before the PNG is finished** — `$LASTEXITCODE` comes back empty/unreliable
even on success, so don't gate on it; wait a few seconds and check the file
exists instead. Write into `build/status/` (a dir you own) — writing to a
*pre-existing* file in `$env:TEMP` (e.g. one created by `New-TemporaryFile`)
silently produces a 0-byte file with no error text; a fresh path in
`build/status/` is the known-good target.
