# gotchas — run-tc-copilot reference

Loaded on demand from `.claude/skills/run-tc-copilot/SKILL.md`. All paths
relative to the repo root.

## Gotchas (all hit for real)

- **YAML colons**: any frontmatter string containing `: ` must be quoted or
  yaml.safe_load throws `mapping values are not allowed here`. `wiki.py`
  reports this as lint L1 instead of crashing.
- **String-matching frontmatter fails after round-trips**: `write_concept`
  re-wraps long YAML lines, so `str.replace` on raw file text silently
  no-ops. Mutate via `read_concept`/`write_concept` (see
  `tools/render_sit.py` for the import pattern). It also normalizes
  block-sequence indentation: PyYAML's dumper writes indentless sequences,
  so a hand-authored `  - item` under a key comes back out as flush
  `- item`. The first `write_concept` to touch a hand-authored concept file
  therefore produces cosmetic diff churn beyond the intended change — files
  the platform already wrote are in that style, so this only ever bites once
  per hand-authored file. Found the hard way during verification; it cost a
  full re-run.
- **Byte-stability requires the fragment-skip check**: renderers must skip
  files whose manifest `fragment_pins` match current fragment hashes,
  otherwise the `generated_from.wiki_commit` pin changes every render.
- **PowerShell resets cwd between tool calls** — start commands with
  `Set-Location <repo-root>` or use absolute paths.
- **`.gitattributes` is `* text eol=lf` repo-wide** — adding a binary without a
  matching `binary` rule makes git CRLF-convert it (a `git add` on an xlsx
  warned "CRLF will be replaced by LF", which corrupts the zip container).
  Rules for xlsx/pptx/docx/pdf/png/jpg/zip exist now; extend them before
  committing any new binary type.
- **A `~$<name>-latest.xlsx` lock file in `build/inventory/<kind>/`** means
  that workbook is open in Excel — expect the `-latest` copy step of that
  suite's next compile to fail (the timestamped file itself still writes
  fine, since its name is new each run).
- **Excel sheet names cap at 31 chars** — `render_xlsx` abbreviates the module
  title word-by-word (`Example Module Name` → `Example Mod Name`); don't
  "fix" the short name in the output.
- **openpyxl `Font(name=..., size=10, **kw)` throws on `size` in kw** — the
  style helper merges dicts (`**{"size": 10, **kw}`) instead.
- Windows console: `wiki.py` reconfigures stdout to UTF-8 itself; don't pipe
  through `Out-Null` if you need the exit code AND output.
- **Reading exported workbooks with openpyxl**: pass `rich_text=True` to
  `load_workbook` or bold cells come back as flattened plain strings — you'll
  wrongly conclude the bold conversion is broken. Verified: `CellRichText`
  cells with `TextBlock(InlineFont(b=True), ...)` runs round-trip fine and
  Excel COM recalc shows 0 formula errors after the rich-text change.
- **Never hand-write the lettered element-verification block** — it's
  generated by `wiki_coverage.element_verification_block(story_fm, ac_id)`
  from the story's component table and is deterministic from that table
  alone; hand-editing it drifts from the coverage map silently.
- **`--force` exists on both renderers** (`render_sit.py --story <id>`,
  `render_production_monitoring_uat.py`) — it bypasses the fragment-unchanged
  skip check, needed when only the render *rules* changed (not the underlying
  wiki fragments), otherwise the renderer no-ops and byte-stability hides your
  change.
- **SIT content lives in `tools/sit_specs/<STORY>.yaml`, not in Python.**
  The per-story `render_vhld_sit.py` / `render_vdtl_sit.py` copies are gone
  (retired 2026-07-31); `tools/render_sit.py` is the one engine. To open a new
  scope, write a spec — never copy the engine. The spec is validated before
  anything is written, so a bad key or a nonexistent AC id fails loudly with a
  suggested correction instead of producing a subtly wrong TC.
- **SIT TCs do not pin the coverage_map** (UAT TCs do, via `COVMAP:` pins —
  verified: 19 of 19 UAT bindings carry them, 0 of 53 SIT bindings do). So a
  coverage_map edit does NOT stale SIT TCs even though their Expected Results
  embed the element-verification block derived from it. Re-render the affected
  SIT scope with `--force` after any coverage re-confirmation. (Closing this
  properly means adding COVMAP pins to SIT bindings — it would restale and
  rewrite every SIT TC, so it is a deliberate follow-up, not a silent change.)
- **The FULL `rtm` graph is unreadable as a tree** — verified this session:
  272 nodes / 621 edges; most edges drop out as "cross-links not drawn" (every
  TC hangs off Components via EXERCISES, every story off several PRD sections,
  resolutions cross-link everywhere), and Tidy tree renders as a thin strip.
  That is not a bug in the viewer — the full graph is for Force / Arc / Matrix
  (which draw the complete edge set). For a readable hierarchy use the separate
  `graphs/traceability` graph instead.
- **The clean tree is `graphs/traceability`, read in the Indented view** —
  117 nodes / 116 edges, only 1 cross-link (one TC covers two ACs). Story-level
  `derived_from` is a many-to-one fan-in (each story ties to ~7-8 PRD
  subsections), which makes a PRD-rooted tree a tangle; `scope_traceability`
  anchors each story to its module's ONE top-level PRD section (§3, §4) so the
  tree has 2 roots, not 44. Tidy tree still crams 72 TC leaves vertically —
  **Indented** (collapsible outline) is the view that reads clearly.
- **`playwright-cli` writes `.playwright-cli/` into the repo root** and
  `smoke.py` fails fast on a dirty tree — it's in `.gitignore` now, but don't
  drop screenshots into the repo root either (write them under `build/`,
  which is ignored).
- `smoke.py` requires a clean working tree (fails fast otherwise) and now
  takes ~3 minutes — see Smoke, above.
- Edge headless screenshot gotchas (see the recipe above): POSIX-style
  `file:///c/...` URLs silently render nothing; the exit code is unreliable
  because the process detaches before the PNG finishes; and writing over a
  pre-existing locked temp file silently yields a 0-byte PNG.
- **opencode plugin directory is `.opencode/plugins/`** (PLURAL) — verified
  2026-07-31 via `opencode debug config`, which lists the plugin under
  `"plugin"` as `file:///.../.opencode/plugins/tc-copilot.ts` with a
  `plugin_origins` entry of `scope: "local"`, discovered automatically with
  zero manual registration; no rename was needed. Helper modules live in
  `tools/opencode/`, NOT beside the entry file — opencode loads every file in
  the plugin directory as a plugin, so a helper there loads as a broken
  plugin. (Live end-to-end blocking inside a real opencode session has not
  been exercised — the configured provider currently rejects its API key on
  every call — so this confirms the plugin *loads* and is discovered at the
  right path, not that a blocked edit is refused live. The hook wiring itself
  is proven by `bun selftest.ts`, not by a live session.)
- **Bun's `$` shell cannot execute `py` on this machine** — discovered
  2026-07-31 building `tools/opencode/state.ts`. `py` is installed as a
  Windows App Execution Alias, and Bun's PATH resolver does a raw `stat()`
  that returns EACCES on that reparse-point type. Verified: `` $`py
  --version` `` throws `ShellError: Failed with exit code 1`, while `` $`cmd
  /c py --version` `` returns `Python 3.14.4`; even an absolute path fails
  through `$`. `tools/opencode/state.ts` works around this by routing only
  the `py` call through `cmd /c` on win32 — keep that pattern for any new Bun
  tooling that shells out to `py`.

## Remaining edges (do not pretend otherwise)

These are properties of the platform, not of any one project's content.

- **A Resolution linking a discarded flow throws a W1 lint warning** for as
  long as it exists. That is expected residue of a discard — a warning, never
  an error, because git history is the discarded flow's archive.
- Deck ingestion is verified against a synthetic pptx fixture only; no real
  deck has been ingested.
- CR classification (editorial|material) is agent work by editing the CR —
  the tooling writes `unclassified`.
- docx PRD input is not implemented (pdf and md are).

## Human-stated stories are outside the cascade

A story aligned through tc-align's Phase A′ (`provenance: human-stated`) has
no `derived_from` and no `illustrated_by`, so `cmd_assert` leaves its
`source_pins` empty. `cmd_cascade`'s story-level needs-review check only
fires by diffing `source_pins` against a re-ingested source's hash; with
nothing pinned it never fires, so the story never flips and its TCs' own
fragment hashes (hashed off the story's own AC entries, same as any story)
never get a reason to change. Consequence: ingesting a PRD later — even one
covering the same scope — cannot stale those TCs through `wiki cascade`.
They must be re-aligned deliberately.

Lint L13 keeps the provenance honest (no unattributed ACs), but honesty is
not the same as coverage of the change model. Say this out loud when a
human-stated story is created; do not let it be discovered later.
