Draft-first generation pipeline

The same protocol as today, with the workbook delivered twice: a labelled draft the moment the set is sealed, and the graded final with a change log when round 2 finishes. Round 2 re-reads only what the improver touched.

T0
You confirm the coverage card
Coverage map and 29119-4 test model, one card, one assert.
T0 + one LLM pass
Draft workbook in your hands
Spec written, rendered, sealed, exported as DRAFT round 0. Review starts.
T0 + about seven serial passes
Final workbook plus change log
Two judge rounds and one improver ran while you reviewed. Change Log sheet lists every difference and why.

Stage by stage

  1. Gate

    Refuses unless the story is aligned with acceptance criteria. The fix for a block is alignment, never a flag.

  2. Propose coverage map and test model

    Deterministic scaffolds, then the agent corrects the map and enriches the model with invalid partitions, both-side boundaries, rule rows, transitions and scenarios. Everything stays proposed.

    LLM pass 1. Output: one coverage card carrying the map, gap dispositions and the test model.

  3. Confirm the card HUMAN

    You confirm or revise. The assert flips coverage and the model to confirmed and refuses if the card and the story file disagree.

  4. Write the spec, render, seal

    One base test case per AC plus technique extras, each naming coverage items. The renderer validates the whole spec before writing anything. Seal records the hashes.

    LLM pass 2. Output: testcases/** and manifest entries.

  5. Draft export NEW

    Writes the org workbook with a visible DRAFT / round 0 mark in the header and the file name, commits as tc-agent, and stores a snapshot of the sealed set (id, hash, the diffable fields) plus the seal commit hash. This is the first cut. wiki next names it as the next command so a weaker model cannot skip it.

    Output: build/inventory/sit/<n>_<ts>.xlsx, build/rubric/<id>-draft.json.

  6. Round 1: pack and judge

    The engine scores the mechanical dimensions and writes four packs. Four judge subagents read one pack each and write verdicts. A verdict on the wrong dimension, unknown test case or wrong rubric hash is rejected.

    LLM passes 3 to 6, in parallel.

  7. Merge, then improve

    The merge produces the round 1 score and the gap report: uncovered items, set-level dimensions below 3, per-test-case dimensions below 3 with the judge's rationale. The improver proposes a patch of set and add operations, each naming the gap it closes.

    LLM pass 7. Output: <id>-r1-patch.json.

  8. Apply, re-render, re-seal

    The patch is validated against the spec's key set and applied atomically. Forced re-render because a spec edit does not move pinned AC fragments. Seal again.

  9. Round 2 with carry-forward NEW

    The engine reads the round 1 patch to find the touched ids: set operations map to existing ids, add operations to new ids. For lenses A, B and C it copies the round 1 verdict of every untouched test case into the round 2 judgment file marked carried_from: 1, and builds packs containing only the touched and added cases. Lens D always gets the whole set. Judges read less; every verdict still describes exactly the content it judges.

    LLM passes 8 to 11, on smaller packs.

  10. Merge round 2, verify

    Score, delta and the regression check. A lower round 2 restores the round 1 spec, re-renders and re-seals. Then lint, RTM, coverage, test model, golden eval, and --round 2 --strict against the configured threshold.

  11. Diff NEW

    LLM-free. Compares the current sealed set with the draft snapshot by test case id and field. Added cases, changed fields with old and new value, removed or retired cases, each joined to the patch operation and gap id that caused it. Header carries the round 1 to round 2 score delta. A restored round 1 yields one line saying so.

    Output: build/rubric/<id>-changes.md and .json.

  12. Final export NEW

    Plain export now refuses unless the latest score for the scope is non-PARTIAL, at or above the threshold, and was computed on the currently sealed set. The refusal is the prose rule from the skill promoted into the CLI. On success it fills the workbook's Change Log sheet, which the org format already has and which is empty today, from the changes file.

    Output: the final workbook, committed as tc-agent.

UAT, same shape

The flow's asserted journey and scenario model stand in for the coverage card, the run-record script stands in for the spec, and the improver patches its wording tables. Stages 5 to 12 are identical with --flow in place of --story. The draft export lands after the first seal of the journey chain, and the touched ids for carry-forward come from the same patch file.

What does not change

Nothing renders before the card is confirmed. Only a human asserts. Exactly one improve round, no third. No verdict is ever edited. Generated files are never hand-edited. Every mutation is a tc-agent commit. The draft is the real rendered set, not a preview of something unconfirmed.
